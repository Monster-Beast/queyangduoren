# 单人与三客机的十分钟对照

此测试复用一轮已完成的三客机长稳数据，另启一个原版单人游戏进程作为对照。两边使用同一台机器、相同 Steam 游戏构建、同一个初始存档、相同游戏速度（原版索引 0，即 1×）和 Unity batchmode。单人过程中只加载测试采样驱动。对照期间关闭其他游戏、基准和重负载程序。

**保存输入指纹。** 使用 `-SoakSeconds` 的运行器在三个 TCP 客机到达 Live 后，自动为存档副本和游戏程序集生成 `soak-input.json`，并在 `host-memory.csv` 记录 Windows 房主进程内存。仍使用旧运行器时可在长稳运行中执行下方命令补录输入指纹。长稳结束时其游戏和存档副本会自动清理。

~~~powershell
.\tests\Integration\Performance\record-soak-input.ps1 -SoakRun .\artifacts\qa\game-857794fa46744b599f4df0e584dab06d
~~~

**在长稳结束后采样。** 脚本从用户的 Klei 存档目录按大小和 SHA-256 寻找同一文件；自定义路径可显式传 `-SavePath`。它将副本装入独立配置，执行预热和十分钟采样，计算结果，再清理私有游戏及存档副本。实际游戏启动和加载通常还需一些时间。开发期间只执行下方第二条命令可单独检查项目编译。

~~~powershell
.\tests\Integration\Performance\run.ps1 -SoakRun .\artifacts\qa\game-857794fa46744b599f4df0e584dab06d
dotnet build .\tests\Integration\Performance\SoloPerf.csproj -c Release
~~~

预期输出包括 `PASS solo` 采样记录和 `comparison.json` 路径。单人记录是新 QA 目录下的 `solo.report`，与连接方同样记录墙钟启动时间、ONI 模拟时间和速度索引。比较器排除第一个约 60 秒的好友加入/引擎预热区间，使用从第一个完整分钟结束到第十一个完整分钟结束的 10 个区间。它校验两组起始模拟时间、速度索引、连续性和客机进度。

速度取两端各自的模拟时间增量除以真实时间增量；下降比例为 `100 × (1 − 联机速度 / 单人速度)`。该量反映 ONI 游戏时钟推进速度，不直接计数 SimDLL 内部步数。比较器同时保存这十个窗口各自的发送/接收速率和主线程网络泵 p95。它报告十个已记录 p95 中的最大值。网络泵日志每分钟最多保留最近 2048 帧的样本，分析时应保留这一取样边界。

报告另列整轮的最大分钟 p95 和各端下行速率。第三端的接收字节数包含其全部重连。验收要求模拟推进速度下降不超过 15%，整轮各分钟的网络泵 p95 不超过 4 ms，每端平均下行不超过 2 MiB/s。超过门槛时脚本先写出原始比值、各窗口数据和判断结果，再以失败状态退出。联网组使用同机三个 TCP 参考客机，持续订阅不同视口、读取状态并周期性重连。真实 Steam 游戏客户端、重施工或后期殖民地可以用同样方法另做对照。
