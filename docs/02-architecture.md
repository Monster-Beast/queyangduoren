# 架构与 ONI 运行时接入

## 代码边界

建议解决方案命名为 QueyangDuoren.sln。游戏适配器先以社区已有项目使用的 net48 为候选，P0 按实际游戏 Mono、Unity 和依赖定版。纯 C# 核心选择可供该游戏项目和现代测试运行时共同引用的目标框架（优先验证 netstandard2.0）。测试/工具选构建机可支持的 SDK 并在仓库锁定版本。避免在核心 DTO 中引用 Unity 对象、原生指针、委托或 Steam 类型。

| 路径（拟建） | 唯一责任 | 依赖 |
|---|---|---|
| src/Core | 世界键、命令、只读显示状态、版本、冲突规则和会话状态机 | 标准库 |
| src/Protocol | 编解码、清单、快照/增量、错误码与版本兼容 | Core |
| src/Transport | 内存和开发 LAN 传输、队列、节流、连接生命周期 | Core/Protocol 抽象，无 ONI 引用 |
| src/Game | Mod 入口、Harmony、角色选择、房主执行与采样、客机显示和工具、Steam 适配 | 上述项目及本地游戏 DLL |
| tests、tools | 协议样本、回放、压力/故障工具、环境诊断、打包脚本 | 纯测试默认可独立运行；游戏测试显式选择 |
| docs/evidence（实施时创建） | build 兼容表、测量、复现步骤、发布核对及最后的待验项 | 小型脱敏记录，大型存档由测试者本机保存 |

数据流为「输入适配器 → 操作请求 → 房主队列 → ONI 游戏线程 → 原生世界 → 状态采集 → 增量 → 客机只读模型 → UI」。网络接收只做有限解析和排队；UI、Unity、Sim 和游戏对象由经实测允许的线程读取/写入。主线程按时间预算分摊采集，编码压缩可下放不可变副本。队列深度、耗时和丢弃计数应可观察。

## 角色和生命周期

- **单人**：默认角色，Mod 加载不改变普通菜单、时钟、寻路、存档或输入行为。新建多人或以副本开房后再启用房主组件。
- **房主**：在世界就绪后建立 session/epoch，监听邀请。游戏原生物理、AI、任务、资源扣除均在此推进。主机玩家的受支持写操作也进入同一排序/冲突路径，避免与客机竞争产生双重提交。暂停时继续泵网络与可暂停态允许的订单，时钟控制立即生效。
- **客机**：在进入可能启动真实世界的流程之前先选定角色。进入只读场景、获得一致基线、补齐增量后开放工具。镜头、缩放、悬浮提示、面板和选区为每人私有。待确认的蓝图或选区用本地预览表现，资源扣除由权威结果决定。
- **退出/切图**：先停止接收新命令，再释放连接、快照、对象映射和视图。取消未完成的后台任务，过期回调按会话代丢弃。退出客机后回到单人存档，主机计时、自动保存、镜头与工具都应恢复。重复进出至少三次。
- **异常**：房主离开，客机显示原因并回到菜单；房主重开存档使用新 epoch。客机渲染失败时禁用写操作、保留日志并支持离开。若启动时补丁签名不匹配，仅关闭受影响的多人入口/能力并报告实际签名和 build。

## P0/P1 技术探针（先验证，再大规模写补丁）

| 探针 | 实施与观察 | 通过条件与替代路径 |
|---|---|---|
| 版本和生命周期 | 从游戏本地 Managed 目录读取程序集版本/哈希；用本机可用的 IL 查看工具定位 Mod 入口、世界加载/卸载、模拟推进和游戏线程调度点。记录类型、重载签名、调用时机、线程及角色。 | 对目标 build 启动、进世界、退菜单，匹配数量符合预期，单人体验通过。在实际探针报告中填写方法；禁止把候选名称当作已验证接口。 |
| 客机停算、UI 继续 | 分别计数物理步、复制人决策、任务执行和存档调用。单独计数渲染、输入与网络泵。暂停菜单或静态截图不能证明停算。房主取消暂停，客机持续移动镜头、打开侧栏、框选挖掘，比较两端计数。 | 房主 tick 前进，客机权威推进及写存档计数为零，显示持续更新。若原生场景初始化就触发模拟，先隔离进入点；仍不可行则用游戏内只读地图、对象代理和输入工具实现同一接口。 |
| 采集与呈现 | 在相同模拟边界读一个区域的元素、质量、温度、挖掘标记、复制人位置和目标；客机通过显示适配器读只读副本。测试固体挖开后气体进入，切镜头再返回。 | 显示随主机新数据改变，悬浮值和叠层取同一版本。若写原生 Grid 会触发副作用，改接渲染/选择的读取入口，验证原生界面和交互。 |
| 挖掘与建筑入口 | 沿工具最终提交点确认输入选择的世界、格子、方向、材料；寻找房主可复用的游戏校验和订单创建路径。框选、拖动、单格都应进入同一语义命令。 | 客机点击只发请求，主机原生施工完成。应用远端状态不会回发命令；主机本地输入只创建一次。 |
| Steam 能力 | 枚举已加载绑定的类型、版本和可用 API；先双账号做邀约、P2P 单往返、断开和二次建房；记录实际回调所有者。 | 确认能借用游戏已有 Steam 生命周期；避免重复初始化/关闭 Steam 或释放他人回调。若 Steam 暂不可测，LAN 可继续开发，Steam 门槛保留。 |

每个探针要有测试 build、最小复现、实际日志、成功/失败判断以及采用的适配器。客机呈现选择由主 agent 在 P1 记录。玩家使用本机原版场景、镜头、叠层和操作界面。自绘面板只用于诊断协议。无法安全驱动原生呈现时记录阻塞及下一项实验，P1 保持待验。

## 世界读取与显示

| 子系统 | 房主采集点或策略 | 客机呈现约束 |
|---|---|---|
| 网格/环境 | 选定已完成的模拟步；按区块采集元素、相态、温度、质量、可见性。用变更通知作提示、轮询已订阅块校验遗漏。 | 固体、液体、气体、热图和 tooltip 以相同快照索引；未知区显示加载中。遵守原版探索遮罩。 |
| 复制人/生物/散落物 | 建立实体生命周期和稳定引用。位置、动画意图、正在执行的任务用可见状态表示。 | 允许视觉插值；实体消亡立刻清理选择和视图。任何代理都不创建 AI、寻路或任务。 |
| 建筑/计划 | 房主创建订单，采集计划、施工、建成、拆除、朝向、材料和侧栏可操作属性。计划与成品可能是不同实体，显式替换。 | 同时显示轮廓和确认状态。选中已被他人拆除的对象时清空面板。 |
| 管网/电网/自动化 | 房主负责连通、流动、负载和信号，按相关层导出拓扑与可见读数，管线和普通建筑分层定位。 | 网络跨出镜头时仍显示房主计算的整网读数。隐藏叠层可降频，重新打开时获取新基线。 |
| 群体管理 | 按版本发布资源汇总、复制人名单、日程、优先级、研究队列和事件。 | 这些全局摘要独立于镜头订阅。客机侧栏的写入口逐项登记；未映射设置明确标为仅房主可改。 |

原生对象 InstanceID、内存地址和每台机器本地分配的 ID 均不能作为跨端引用。房主为实体分配 session 范围内不复用的 ID；对象重建时发删除和新建。世界键显式包含 worldId，格子定位含坐标/层；收到越界坐标由房主拒绝。发现模式、代理、回调、游戏对象映射、私人 UI 状态均不写入单人存档。
