# 联机施工靶场

靶场用 Windows Steam 基础版《缺氧》764025 运行。房主载入基础存档的副本。客机运行同一版本和同一份 Mod，按正常联机流程接收存档。每次测试从同一份起点重新开始，便于比较修复前后的画面。

## 自动施工工位

当前 `-CheckConstruction` 用房主原版放置入口在附近放一个储物箱蓝图。双方随后对照三个阶段。下单和放置使用原版，运料、施工以及生成成品由房主原版模拟完成。

1. **蓝图刚下单。** 双方能选中同格的蓝图，核对待施工的 ID、施工值及已送达的公斤数。
2. **实际施工中。** 中间值达到约 28% 后暂停，让双方分别取画面并核对同一 ID 的实际施工比例和材料量。之后恢复，让同一工单继续完工。
3. **完工。** 对照成品对象的 ID，检查客机不再能选中旧蓝图，并截图保留两侧画面。

阶段断言读取原版房主施工对象和客机同步后的对象数据，并单独读取两端实际的进度条控件。施工中检查条是否可见、条长是否跟随同一百分比。完工后检查旧条是否消失。配对截图用于核对画面位置、建造动画和侧栏。

本机有之前双端验收使用过的第 3 周期隔离档副本 `artifacts/qa/range-starter/Fixture.sav`。两端账号仍需持有游戏、互为 Steam 好友。开始前退出游戏副本，保留两个 Steam 客户端。运行时在 `artifacts/qa` 新建独立记录目录，复制输入存档并校对原始哈希。下面的账号变量由本机操作者填写。

~~~powershell
$save = '.\artifacts\qa\range-starter\Fixture.sav'
$package = '.\dist\QueyangCoop-0.3.2-construction-preview.zip'
.\tests\Integration\Game\steam-dual.ps1 -HostSteamId $hostSteamId -GuestSteamId $guestSteamId `
    -SavePath $save -PackagePath $package -CheckConstruction -SkipManagement
~~~

运行成功时，两边报告都出现三个 `CONSTRUCTION_RANGE` 阶段，目录里有 6 张 `range-*.png`。录屏和普通重连验收由既有双端脚本继续执行。若施工阶段超时，先看两端报告中的阶段、格号、已交付质量和施工数值，核对原版复制人有材料、有路可走且正在施工。

首次复现使用 15EB 血条预览包。格 49788 的同一蓝图 ID 2357 在两端均为 0% → 28.2%，客机中间记录为 400 kg 已交付，完工后同为成品 ID 2369。原版施工进度条在房主画面可见，客机画面只有施工效果和侧栏数据。该轮完成重连和带 Mod、无 Mod 两种独立读档。[修复前的两端截图](evidence/qa/dual-construction-range.jpg)

## 研究与余量工位

以下开关可以单独运行，也可加到同一份双端脚本命令。在施工预览包上使用 `-CheckConstruction`。研究、余量和供电提示需要带工作条、设备表计和建筑警告同步的新构建。

| 开关 | 控制条件 | 两端断言 |
|---|---|---|
| `-CheckResearch` | 房主在客机入房后建出原版研究桌，选择可开始的科技。通过游戏的研究点接口增加两次点数，再让原版工作条隐藏。 | 两档点数/所需点数、同一实际条长、停工后隐藏；客机保持选中仍可读到点数。这个工位控制原版数据变化，完整的复制人供电、运料和研究工作另测。 |
| `-CheckBattery` | 原版电池实例依次充入容量的 20%、72%，然后放到 0。 | 实际原版表计动画帧与焦耳读数。 |
| `-CheckReservoir` | 向原版储液库注入水，再提高储量，最后取走一部分。 | 实际原版表计动画帧和界面中的储量。 |
| `-CheckPower` | 在隔离副本里改变研究桌原版供电组件的三种输入。 | 两端从原版世界图标渲染器读出未接线、已接线但没电和正常供电。正常供电阶段尝试让本地重新加入旧提示，检查它是否仍被拦住。此工位控制供电状态，没有铺设线路。 |
| `-CheckAreaDig` | 一名客机玩家通过原版工具一次框选 3×2 的天然矿格，房主再让复制人工作。 | 同一批格子逐格检查工单和唯一发起人；跟踪同一个实际开挖的格子，核对原版挖掘条至少两次增长、完工清空矿格且进度条移除。 |
| `-CheckAlert` | 客机用原版优先级工具把一张挖掘单从 5 改为紧急，再改回 5。 | 房主真实工单优先级和两端原版全屏黄警图层颜色。 |
| `-CheckSweepSymbol` | 房主让同一个原版储物箱的“仅限清扫”依次关闭、开启、关闭。 | 两端绘制的 `sweep` 符号是否出现、是否移除。 |

有的建筑在世界里画工作条，有的用独立设备表计，还有的只在操作面板里显示。前两类现在从房主的原版组件取得实际显示值，选中建筑的数据仍走状态和储量面板。每种建筑的专有面板需要按实际操作核对，尤其是同一建筑上同时发生多个作业、不同类型余量相互独立的场景。

## 建筑工作动画

`-CheckResearchMotion` 给研究台和电池铺设原版电线，放入泥土并选择基础科技。原版复制人接取研究工单后，检查研究台有有效电路、研究点数自然增长，并从同一台研究台的机身渲染器读取 `working_loop` 实际显示的相对帧。验收要求主客机分别看到至少两次循环，并有相同的工作帧。该工位与只检查研究进度条的 `-CheckResearch` 可以独立运行。

`-CheckBuildingMotion` 用原版手摇发电机的 `working_loop` 检查另一种机身循环，并用电池的原版充放电接口按 200 毫秒递进。两端从手摇发电机机身和电池表计的渲染器读取实际帧。每个工位都分别保存主客机截图、帧序列和窗口录像。

双 Steam 靶场默认将客机开为 1040×650 的窗口，主机为 1280×800。运行时可以用 `-GuestWidth` 和 `-GuestHeight` 调整客机大小。这些启动参数只用于隔离测试。

## 后续逐项覆盖

| 工位 | 原版状态切换 | 对照项目 |
|---|---|---|
| 建造墙、家具、管线 | 供料不足 → 供料齐 → 施工 → 完工；再做取消、拆除 | 安放位置和方向，各阶段真实条宽、材料、覆盖层、工单消失 |
| 微生物压制器、研究站 | 入队 → 运料 → 开工 → 停电或离岗 → 继续 → 产出 | 配方队列、研究进度、当前工人、工作循环、原料消耗和产物 |
| 蓄电池、水箱、洗手池 | 开停电、充放电、进出液、净水耗尽 | 原版侧栏数值、建筑表计、警示图标及相关动画 |
| 植物、孵化器、发光虫 | 生长及凋萎、孵化和破壳、活动光源 | 进度、状态变更、动作与特效，切镜回看和重连后核对 |
| 受伤复制人 | 受伤 → 医护 → 恢复 | 血条、动作、病床状态和床位分配 |

先取低、中、高、不动四个明确时刻，并分别测暂停、恢复和重连。每个工位留一份两端截图、建筑格和对象 ID、真实数据日志。录像比较进行中的变化和画面延迟。
