# 协议、传输和状态一致性

以下为 v1 实施合同。具体数值是原型默认预算，可在压力测试后统一调整并记录实测原因。同一协议适用于内存、开发 LAN 和 Steam。每次更改线格式都要同步 golden vectors（固定字节测试样本）、版本和两端实现。

## 连接和消息

状态机为 Disconnected → Connecting → Negotiating → ReceivingBaseline → CatchingUp → Live → Closing。仅 Live 能下达玩法命令。连接阶段各有超时、进度和可读的失败原因；任一阶段离开都能释放资源。暂停游戏只停止模拟时钟，网络时钟使用单调实时时间。

| 消息族 | 最小内容 | 交付语义 |
|---|---|---|
| Hello/Welcome/Reject | 协议主次版本、Mod 版本、游戏 build、内容包 ID、影响模拟的 Mod 清单/哈希、功能位；房主返回 sessionId、epoch、peerId、上限及协商结果 | 可靠；首版要求相同 build、Mod 和内容清单；未知主版本拒绝，次版本仅在双方支持相同必需特性时协商 |
| Subscribe/BaselineBegin/Chunk/End/Ack | 视口范围、订阅代、snapshotId、基准 revision、水位、manifest、块索引、尺寸、各块及总哈希 | 可靠分块、限速、可取消；按完整清单校验后原子切换；回 ACK 后释放已引用的基线 |
| Delta/Applied/Resync | epoch、订阅代、fromRev、toRev、同一范围的增删改；客机已应用修订与原因码 | 结构和玩法状态可靠有序；缺口触发补发/新基线。同一批跨对象变化一起应用 |
| Command/Result | connection generation、commandId、kind、target、typedPayload、必要前置版本；结果含 Accepted/Rejected/Partial、原因、提交序号、各目标结果及关联 revision | 可靠；房主去重，相同请求返回相同结论。接受代表原生游戏已经登记操作，等待复制人执行期间仍显示未完成 |
| Presence/VisualSample | 玩家光标、可选镜头位置、动画插值样本，带序号和时间戳 | 可丢、可合并、过期丢弃；不得用作建筑存在、资源余额或地形的唯一信息 |
| Ping/Pong/Leave/Error | 时钟样本、心跳、关闭原因、诊断代码 | 暂停时有效。连接身份来自传输层绑定；关闭会清理该 peer 的订阅、预算和未提交请求 |

**帧格式建议。** 固定小端二进制，v1 首部依次为 magic u32（ASCII 字节 QYMP）、major u16、minor u16、messageType u16、flags u16、payloadLength u32。按消息类型定义后续字段；协商后权威消息必带 sessionId（16 个原始字节）、epoch u64 和适用的 revision/sequence u64。固定宽度整数，文本 UTF-8 前置字节长度，数组前置项数，布尔值为 0/1。浮点限制有限值，温度与质量在 schema 里注明单位（K、kg）及精度。每种字段、压缩算法/版本、枚举、空值和错误码在 Protocol 工程维护单一注册表。预留 ID 不复用。v1 默认无压缩，协商一致且基准测试获益后才引入压缩。

**传输。** 开发 LAN 先用 TCP 显式按帧长读取（处理拆包/粘包/半关闭），默认回环，双机开发时指定 LAN 地址。Steam 使用游戏已有绑定，Lobby 管邀请与元数据，数据走实际确认可用的 Steam P2P Sockets。监听连接请求时检查房间、实际 Steam 对端和席位；同一 Steam 身份重连替换旧连接。游戏命令身份由连接绑定推断。Steam 接收的消息拷贝后按绑定约定释放。LAN 的测试身份只适用于受控测试环境，正式 Steam 包默认不开放 LAN 监听。

## 顺序、并发与幂等

1. 全局 simTick 表示主机模拟步；worldRevision 表示权威可复制状态提交。暂停时下令仍可增长 revision。网络线程向游戏线程入队，主线程为来自房主和客机的操作分配单调 commitSeq。重连不会复用旧连接的身份代。
2. 每连接命令顺序递增，标识用 (sessionId, epoch, peerGeneration, commandId)。房主保存最近结果及已处理序号水位。已知重复重放结果；早于缓存窗口的重复返回 Expired 并要求刷新，永不再次执行。客户端断线把未确认请求显示为状态未知，重连观察房主状态，由玩家决定是否重新下令。不得在新 epoch 自动重放。
3. 以格子、层和实体为粒度检查条件。两个玩家建同一占用层，主机顺序执行，后到者取得 Occupied；序号一致的重复包复用结果。批量挖掘按稳定顺序裁剪到边界，非法输入拒绝；有效区域内已挖、不可挖和成功项分别返回。取消针对具体计划 ID，失效目标返回 TargetGone。侧栏设置使用目标属性版本，陈旧编辑返回 Conflict 和当前值。
4. 房主按原生规则校验可见性、合法目标、材料种类、建筑解锁、朝向、施工和操作权限；建筑材料的实际搬运与消耗时点沿用游戏规则。每 tick 有每 peer 命令/格子配额。只有房主命令能调整倍速/保存。未知操作返回 Unsupported。待确认预览与权威视图独立，拒绝、超时或实体替换后清理。
5. 可见实体、格子和全局摘要作为一个提交批次。Result 与 Delta 即使跨通道先后抵达，也按 commitSeq/revision 对账。接受命令到原生异步效果之间保留订单状态，后续施工完成是另一条状态变化。

## 晚加入、换视口与断线恢复

1. 房主在一致的游戏线程提交边界冻结显示模型版本 R（可用不可变块/写时复制），发送该订阅范围和全局摘要的 manifest。分帧采集要保留 R 对应的副本/变更日志，严禁把不同时间的格子拼成同一版本。原型可测量短暂房主停顿；发行门槛以实测预算为准。
2. 客机在临时副本重组，验证索引、长度、解压后上限和哈希；同时保留 R 之后的有界可靠增量。组装完成后一次切换，再顺序追到房主水位，发送 Applied。若 R 已落后于房主环形日志最早保留值，丢弃临时副本并取新基线。
3. 全局 revision 可因视野外修改而前进。为每个订阅流维护连续 fromRev/toRev；过滤掉的全局变化也允许发送空推进水位。定义缺口为 fromRev 与客机该流应用水位不匹配；切视口增加 subscriptionGeneration，旧代包全部丢弃。进入新块先下发基线，再接受该块增量。实体跨块通过同一权威实体 ID 更新，按订阅并集计算添加/移除，消除边界重复。
4. 客机只在确认同会话、同 epoch、同订阅范围且断点仍可补发时做增量续接；首版允许所有重连直接取新快照。房主读档/重开创建新 epoch，清空旧映射、旧订单结果和显示缓存。主机自动保存不改变 epoch。
5. 同一 revision 和范围比较规范化状态摘要，按坐标/实体 ID 排序，剔除纯动画/本地 UI，并使用同一量化规则；发现偏差先重新订阅相关块，仍不一致则重新取基线。记录首个分歧字段。客机加载/超时不可阻塞房主和其他玩家。

## 初始容量和降级策略

- 建议网格块 32×32，快照块有效载荷 32 KiB，单帧上限 64 KiB，单次解压后快照上限 128 MiB；超限明确报错或缩小订阅后重试。块传输窗口先取 8，按确认和传输待发字节调整；完整快照只在新基线时使用，不作为单条 Steam 消息发送。
- 主机结构提交先按 10 Hz 刷新，视口温度/气体采样可先 2–5 Hz，位置显示可先 10 Hz 并插值；这些是复制频率，与原生模拟步解耦。结构基线始终包含可靠的位置/属性，丢失视觉样本可自动恢复。订阅最大视口、单批格子数（初值 256）、每 peer 队列字节数（初值 4 MiB）有硬界限。大视口分片、批量输入拆分并反馈进度。
- 发生背压时先合并光标和连续读数，再降低环境层采样；可靠变更历史溢出则令慢客机重新取基线，持续超时断开该客机。避免在队列满时反复同步而无进度；记录累计重基线次数、峰值内存、滞后与断开原因。对碎片、重复块、非法长度、未知枚举、无效坐标、过期会话和压缩炸开后的尺寸做边界测试。
- 所有索引、长度与内存预算在分配前检查。协议仅承载已登记的 DTO；网络数据不得指定运行时类型或调用任意游戏方法。日志用会话内匿名 peer ID、命令号和修订号关联，调试转储默认省略好友标识和存档内容。
