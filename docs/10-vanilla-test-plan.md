# 《缺氧》Vanilla 联机待测试清单

基线为 Windows Steam、Klei 764025、基础游戏同一殖民地、同一游戏与 Mod 构建。当前起点为 `db8d8dd` 的大图入房预览包。玩家在各自安装的《缺氧》中使用原版工具、建造菜单、侧栏及确认流程。测试既要核对原版控件，也要核对命令后的主机实际状态、其他玩家收到的结果和存档读回。

主回归图为 **The Doomed Laboratory（第 148 周期，22 名复制人）**，双 Steam 已核对 **4,580 个成品建筑实例**。**Impenetrable Spacerock（第 1160 周期）**覆盖 24,851 个成品和 181/295 种建造菜单建筑，用于大图压力和独有工位。现场建筑、可触发的工作、客机显示、客机操作、重连读回分别留结果。[148 周期实测](evidence/doom-lab-148.md) · [大图入房记录](08-test-range.md#以-1160-周期档做大图回归) · [逐建筑待验证表](10-vanilla-buildings.tsv)

从 `M` 起步的地点为冷藏箱 (127, 196)、燃煤发电机 (95, 180)、养殖站 (81, 180)、普通研究台 (115, 203)、高级研究台 (118, 203)、大电池 (100, 207)。`L` 的独有压力工位包括蒸汽轮机 (99, 166) 与氢气引擎 (32, 320)。开测前核对供给、权限和可触发的工作，缺失设施写入场景准备单。[原始工位记录](08-test-range.md#成熟殖民地候选)

**优先级**。P0 阻塞入房、运行、正确性或恢复。P1 为高频原版合作操作和主要系统。P2 为基础版专用面板、低频与终局场景。正常操作优先使用原版 UI。夹具可用来布置电、水、伤员和倒计时；实测结果要注明事件来自原版实际运行、夹具触发或二者。

每个用例的状态取一个值：**待测、准备场景、失败、已修待回归、通过、受阻、不适用**。已有的历史证据在表中标为「已有样例」。最新固定包、目标存档、当前环境、完整操作路径都满足时才记录该组合通过。未实现的原版客机写入口记录「失败」及其具体入口。原版本身按科技、材料、DLC 或状态禁用的控件记录原版对照和提示。需额外 DLC 的效果在 Vanilla 行标为不适用，并登记相应的兼容测试。

### 执行顺序

1. **P0 起点**。常规项从 148 周期档的短时单人、双 Steam 运行基线与已报告的动物生命条开始，随后按 MAP-02 至 MAP-04 顺序推进。1160 周期档保留固定输入，单独跟踪长时、大图视区和同机性能。
2. **P0 一致性**。执行 NET、VIEW、CMD、SAVE 的 P0 项，跑完「客机操作 → 主机执行 → 两端显示 → 晚加入/保存读回」。一次修复对应一个可复现失败。
3. **P1 高频闭环**。先执行 FAC-01 至 FAC-04、BUILD-01 至 BUILD-04、DUPE-01 至 DUPE-05、MGR-01 至 MGR-06。随后按系统组补环境、运输、动力和动画。
4. **P2 覆盖与发布**。按逐建筑表补齐 114 个缺少的类型和已有实例无法触发的状态，再按本表测试其专有入口。最后做多设备、3/4 人、大档长稳与安装回滚。任一环境失败保留该环境待办。

## 5. P1/P2 系统场景与专用原版面板

逐建筑表每个 prefab 都要执行 BUILD-01 至 BUILD-03 的适用项与表中关联的系统场景。用例里的设备是触发实例，未建的 prefab 按同组工况逐一验证自己的显示和控制。若同一功能用不同组件实现，在记录中分别填写实际原版入口。难以施工的遗迹、故事对象、专业生产和火箭另有专用用例。

逐建筑表以 prefab 为唯一键。`Built1160` 为原版载入后的成品数，`OperationalSeen` 和 `ActiveSeen` 分别为历史短时采样中见到可运行或正在运行的实例数。三个坐标字段给出一个可见实例，`-1` 表示没有选出可见实例。`Placement`、`State`、`Operation`、`SaveAndRejoin` 分开登记。表里预填的 `pending` 表示等待对应验收，即使地图上已有该建筑。`existing_object` 行表示扫描实际见到的非建造菜单对象，适用的发现、交互和读档保持待测。

## 7. 复测脚本和证据登记

现有脚本可直接用于已具备夹具的项。从仓库根目录运行下面步骤。Steam 参数用本机已授权的账号变量。先确认两个游戏实例已退出，准备固定包和隔离存档。

~~~powershell
dotnet test .\tests\Core.Tests\Core.Tests.csproj -c Release --nologo
dotnet build .\tests\Integration\Game\SmokeDriver.csproj -c Release --nologo
~~~

成功时核心测试输出通过计数，驱动能使用对应的游戏程序集构建。构建时若 Steam 安装不在默认位置，将 `ONI_GAME_DIR` 指向包含 `OxygenNotIncluded.exe` 的目录。两端选择同一份固定包。同组工位共享一次开房，按各自的前置条件依次执行，每项单独记状态。148 周期连通性批次可同时覆盖首次入房、重连、独立镜头与动物红条。

~~~powershell
$test = @{
    HostSteamId = $hostSteamId

}
.\tests\Integration\Game\steam-dual.ps1 @test -CheckColonyJoin -CheckColonyBatch -CheckCritterHealth -InviteWaitSeconds 0
~~~

### 测试、修复、再推进

1. 先跑对应原版最小复现。记录首个失配点属于输入、资格校验、主机真实执行、视区/协议传输、原版控件或渲染、存档读回的哪一处。
2. 用相同输入记录失败。修复保持原有控件和主机权威路线。对晚到请求、同帧冲突、离屏删除和旧存档补相邻回归。
3. 重新钉死修复包，从同一原始档重跑失败用例、相邻的用例和一次小档烟测。地图问题另到大档做暂停及未暂停证据。修复的状态从「已修待回归」进入「通过」。
