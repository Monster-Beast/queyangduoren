# 同机双 Steam 账号验收

Windows Steam 基础版《缺氧》，Klei 764025、Steam build 26798728。A 使用普通 Steam 客户端，B 使用官方 Sandboxie-Plus 内的第二个 Steam 客户端。Steamworks 在各自的游戏环境中核对当前账号、好友关系和 App 457140 的所有者。两人各自拥有游戏。原始游戏文件、玩家的 Mod 配置和输入存档在测试前后核对哈希。个人账号、原始邀请记录和存档留在本机。

## 0.3.1 同屏画面和工单归属

实测包 0.3.1-dev，143729 字节，SHA-256 为 `92A0B7902F8899CFE57E6282576148CA876806080313DD519999F94D1150215C`。运行 `steam-dual-89c20505c7684108a42fdaf80860f421` 用该包点击了两轮真实 Steam 聊天邀请，在原版窗口验证以下结果。

| 玩家看到的问题 | 两端对照 |
|---|---|
| 挖掘标记向上偏 | 旧客机用格中心放图标，相对原版格底高 0.49 格。新客机复用原版工具基准、图层和深度。分别由 B 和 A 下单时，对照实际图标网格、材质、世界中心及包围盒，各分量实测误差为 0，容差 0.005 格。拖地工具也改用对应原版基准；两次几何测量针对挖掘。 |
| 复制人位置不同 | 从房主真实动画采样帧 4228 对照存档 ID 79、81、83。两端的角色根坐标、送入渲染器的矩阵和最终动画帧分别吻合，客机每个 ID 只有一个可见渲染器。79 和 81 在房主本身就位于同一处。测试在暂停的对照帧测量，运行中画面还会受到网络采样间隔影响。 |
| 右侧资源有名称、缺数量 | 客机收齐房主库存页后通知原版 UI 首次计数已完成，刷新置顶栏和打开的资源表。火成岩在两端置顶栏均显示 39.1 t；从客机点击「查看全部」，通过原生面板读到可用 39.1 t、总量 43.1 t、预留 4000 kg。 |
| 同一种工单看不出谁下的 | 在同屏两处活动挖掘工单上，两端实际绘制了 P1 蓝色 `#3BC7FC` 和 P2 橙色 `#FFA326` 的编号徽标，悬停提示各自匹配 Steam 昵称。完工订单撤下徽标，另一条未完订单在客机退出重连后仍显示原作者。原存档已有的挖掘工单没有被标成房主创建。 |

此运行的两端界面、命令及重连对照通过，最后保存证据时夹具选用的一条旧挖掘任务已被复制人自然完成。它不能单独证明退出房主进程再读档后的结果。

同包复测 `steam-dual-39ae9791013d4cd6bfe82561959f1200` 接受了实际送达的好友邀请。房主帧 2534 对应的三个复制人在客机逐一匹配。隔离房主写出 770996 字节存档，带合作 Mod 重开验证了工单归属，另一个无合作 Mod 的进程也成功读取原版工单。

### 正式配置文件的变化

早期读档夹具没有显式设置 Steam App ID，启动了正式 Steam 游戏进程。没有打开玩家存档，输入存档校验相同。正式 `mods.json` 和 `kplayerprefs.yaml` 出现写入，缺少事件前的字节备份，无法还原或确定当时是否有设置改变。此后每轮另存两份文件的前后副本，启动时显式设置 Steam App ID。后续一次偏好文件变化只增加了两个空行。保留玩家当前配置。

### 0.3.1 未暂停的动作基线

同一台电脑用两个实际游戏窗口录制 24 秒，同时记录 35 秒渲染采样。复制人 83 在房主和客机全程可见。客机绘制了 3369 帧，但角色动画只切换 141 次。下表统计相邻两次真正切换之间的间隔，未计入观察窗口两端的不完整间隔。

| 窗口 | 切换次数 | 中位数 | P95 | 最长 |
|---|---:|---:|---:|---:|
| 房主 | 590 | 48.94 ms | 108.99 ms | 244.12 ms |
| 客机 | 141 | 251.09 ms | 400.23 ms | 655.57 ms |

这轮 Unity Mono 的 Stopwatch 在两个进程中使用不同时间原点，因此只能计算各端自己的切帧间隔。候选版改用 Win32 QueryPerformanceCounter 对齐同机记录。统计命令为 `python tests/Integration/Game/analyze-motion.py artifacts/qa/steam-dual-c041bc3fe22a452aa392b935e143c1f4 --independent`。

## 好友邀请、下单与重连

在 0.3.0-dev（ZIP SHA-256 `398CB883BC2410AE0988A4F6758F581F1A47242EA83BCC747253167B282604DC`）上运行两个可见的 Unity 游戏进程。房主载入第 3 周期的独立档，客机停在主菜单。测试夹具核对好友后，用 Steam 的 `InviteUserToLobby` 向 B 定向发送邀请。两轮均在 B 的真实 Steam 聊天中点击“进行游戏”，两次都观察到 Steam 派发 `GameLobbyJoinRequested_t`，随后由 Mod 的正常入口加入。房间有两名成员，房主接受了一个 Steam P2P 连接。

| 在原版界面做的操作 | 两端实际观察 |
|---|---|
| B 用挖掘工具点击 (120,192) | B 收到工单回执，A 的原版地图生成挖掘工单。测试给隔离殖民地的工单提高优先级后，复制人 83 实际施工，格内变为氧气。 |
| B 退出，A 再次邀请 | B 第二次收到全新的存档，在首帧地图更新前就从存档读到了挖空后的同一格。 |
| A 用原版工具在 (119,192) 下单 | B 先确认该格没有挖掘标记，随后观察到生产同步视图和原版场景里同时出现了新工单。 |

这组实测对应本机 `artifacts/qa/steam-dual-e2264681d49e4e28bb35d6fa6e861a27`。更早用第 39 周期档验证了房号加入、P2P 存档传输和 B 下单。该轮选中的格子在 210 秒内没有完工。后续运行从房主的原版寻路和挖掘技能数据选目标，分别核对下单、工人实际施工和最终地图变化。

同机隔离测试覆盖两个身份和两套实际游戏画面。异机公网质量、四名真人和 DLC 需要各自的实机环境。

## 在同一台 Windows 电脑复测

先让普通 Steam 和 Sandboxie-Plus 内的 Steam 分别登录两个互为好友、各自拥有游戏的账号。关闭当前的《缺氧》游戏窗口，保留两个 Steam 客户端在线。测试人员将两位玩家的 SteamID64、包和存档路径填入本机变量。脚本在 `artifacts/qa` 下生成两个游戏和配置副本，同时检查原始输入的哈希。

~~~powershell
.\tests\Integration\Game\steam-dual.ps1 -HostSteamId $hostSteamId -GuestSteamId $guestSteamId -SavePath $savePath -PackagePath $packagePath
~~~

默认沙箱名为 `QueyangCoopLoginB`，其他名称用 `-BoxName` 指定；自定义重定向目录用 `-BoxRoot` 指定。测试会启动两个游戏，打开 B 的 Steam 好友聊天，分别点击首次加入及重连时收到的《缺氧》邀请。报告区分邀请送达、接受回调和等待期结束后的房号加入。原始报告可能含 Steam 标识，只在本地查看。
