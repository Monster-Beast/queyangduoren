# MAP-01 · Impenetrable Spacerock 运行基线

测试使用 Windows 基础版《缺氧》764025，1160 周期起始档 SHA-256 为 `A4F6D42F74D8F5E52AC5395C3FF359B62BCE3F48E1C388E989697FCA3A93C423`。联机模式固定使用大图入房预览包 `4B1DFA87AB7E7D3D3642E1E1322329FC2EA87F5F25BE7108E1717D5E40CE4413`。每次复制同一份输入到独立测试目录并核对原档哈希。

单人、带 Mod 的空会话及 Steam 空房均使用同一台主机，1280×800、窗口模式、原版 1 倍速。镜头依次移到冷藏箱 (129, 193)、蒸汽轮机 (99, 166)、养殖站 (140, 174)，倍率 12，每段采样约 12 秒，包含切换镜头。用 Unity 未缩放帧间隔计算 p95，`GameClock` 读取主机模拟推进。原版单人进程只加载观测夹具，未载入联机程序集。

| 模式 | 观察目录 | 模拟秒 / 实际秒 | 三段帧间隔 p95（ms） | 原版错误 |
|---|---|---:|---|---:|
| 原版单人 | `map01-2e950f5f50054defabaae7a5239b2fb6` | 35.063 / 36.018 | 44.25 / 24.26 / 29.40 | 0 |
| 开启联机 Mod、不开房 | `map01-c4887ca9fd104247afbc66c2ed64bbe3` | 34.313 / 36.024 | 53.04 / 26.64 / 32.18 | 0 |

上述三次观察均未复现石壳哈奇幼体任务异常。每个模式留了三张原图和逐段日志。下图从左到右是同一蒸汽轮机工位的单人、不开房和空房。结果反映本轮短时运行，仍需跑 10 分钟性能基线与同机双端对照。[三种工况截图](qa/map01-single-room.jpg)

空房夹具最初把观测 DLL 注册为第二个启用的 Mod，触发联机包的单 Mod 限制而没能入房。观测 DLL 现放在测试目录中的同一个 Mod 项下，空房复测通过。发布包保持原哈希。

## 同机双 Steam，解除暂停

运行 `steam-dual-54f109a293544e55b81c00baa53f6db2`。客机以 1040×650 小窗接入，主机保持 1280×800。入房时对齐 24,851 个成品实例。随后使用与前三次相同的目标坐标、倍率和采样时长，房主开 1 倍速。客机表里的模拟秒是视区同步过来的时钟读数。

| 端 | 模拟秒 / 实际秒 | 三段帧间隔 p95（ms） |
|---|---:|---|
| 房主 | 13.188 / 36.794 | 655.54 / 827.37 / 580.59 |
| 客机 | 13.126 / 36.448 | 521.08 / 754.67 / 539.71 |

**未通过流畅运行验收。** 房主正常推进约 36% 的实时速度，两个窗口有明显卡顿。主机在生成入房用原版存档后约 10.4 秒，记录石壳哈奇幼体的原版任务恢复异常 `StateMachineSerializer.Entry.Restore → FastReader.ReadKleiString → IndexOutOfRangeException`。帧时间和任务错误的因果关系仍待查。主机的 `CoopSession.Pump` 日志使用 60 秒汇总，不能和每段的整帧 p95 直接相减。下一次性能定位按测试阶段记录主机采集及客机应用耗时、独立内存和系统换页。[双端运行截图](qa/map01-dual-runtime.jpg)

## 石壳哈奇幼体任务恢复

在同一份档打开 Steam 空房，无客机连接时从夹具调用真正的 `CoopSession.CaptureNativeSave`，然后恢复 1 倍速走固定路线。旧包的冷快照再次触发同一条异常，这把复现范围缩小到主机捕获快照后的恢复。旧包先让模拟推进 12 秒，再捕获快照，此次未复现。Klei 764025 的 `SaveLoader.Save` 会调用 `KSerialization.Manager.Clear`，清空读档模板和映射。早期载入的状态机还有延迟恢复任务，在失去原模板时走到了错误的二进制读取位置。

修复限制在联机入房快照入口。调用原版保存前切换到临时读档缓存，保存完成或抛出异常后恢复房主当前加载的三份读档缓存。原版存档格式与原版手动保存入口保留。

| 工况 | 运行目录 | 模拟秒 / 实际秒 | 观测到的原版错误 |
|---|---|---:|---:|
| 旧包，冷快照 | `map01-4e1a066dda734b029be63e327dcf9640` | 34.938 / 36.055 | 1 |
| 旧包，先推进 12 个模拟秒 | `map01-bc5e3f675e9142deadd53907dd9ba30d` | 36.125 / 36.015 | 0 |
| 修复包，冷快照 | `map01-ed5883aa252341c586f45ab7b69c0d3d` | 35.125 / 36.018 | 0 |

修复包哈希 `872666AEE671FFA095743D1A551C3FFD29BCB374AA8107FCA1AFAC7B883DBEBF`。复测无需先运行殖民地。截图左侧为旧包，右侧为修复包，各取冷快照后同一段路线。[快照修复对照](qa/map01-snapshot-fix.jpg)

## 修复包双 Steam 回归

运行 `steam-dual-ebbf407b80e64d669da9fa6efa092708`。两端完成首次真实入房，对齐 `24851/6A0AF8077B0B50577CE73E70`。房主生成冷快照后在 1 倍速按相同路线推进，两端日志均未出现石壳哈奇幼体的恢复异常。原始输入哈希一致。截图每行左房主右客机，从上到下为入房、冷藏箱、蒸汽轮机、养殖站。[入房和三个工位双端截图](qa/map01-dual-fixed.jpg)

| 端 | 三段累计模拟秒 / 采样墙钟秒 | 三段帧间隔 p95（ms） | 三段联机 Pump p95（ms） |
|---|---:|---|---|
| 房主 | 14.688 / 36.866 | 925.03 / 529.19 / 525.02 | 20.79 / 17.94 / 18.11 |
| 客机 | 14.313 / 36.526 | 487.52 / 454.18 / 441.68 | 7.87 / 5.79 / 5.81 |

**冷快照回归通过，同机大图流畅度失败。** 房主在采样区间以约 40% 的实时速度推进。入房附近系统可用内存一度只有 244 MiB，另一个样本为每秒换入 19,738 页。第二段有两个采样点的页读取回落到每秒 3 次与 0 次，房主该段仍有 529 ms 的帧间隔 p95。系统计数每约 4 秒采样，无法把单次慢帧归因到磁盘或确定整个运行阶段的阻塞来源。两端 Direct3D 日志同时出现垂直同步和时间戳回退告警。联机 Pump 的阶段计时只涵盖该方法，不能直接从整帧 p95 中相减。

### 垂直同步对照

运行 `steam-dual-6f55fd6397264d6aa5e8bb23497f231c`。保持同包、同档、同机、同镜头路线与 1 倍速，在两端采样期间令 `vSyncCount=0`。这轮用操作系统单调计时器直接量相邻采样帧的间隔，避免依赖 Direct3D 告警所涉及的 Unity 帧时钟。房主全程在前台，客机在后台，双方仍对齐 24,851 个建筑实例。

| 端 | 三段累计模拟秒 / 采样墙钟秒 | 三段帧间隔 p95（ms） | 工位采样中的工作集 / 私有内存（约 GiB） |
|---|---:|---|---|
| 房主 | 14.688 / 36.489 | 716.63 / 497.63 / 807.37 | 5.3 / 8.3 |
| 客机 | 14.251 / 36.481 | 436.94 / 435.95 / 572.87 | 3.4 / 8.1 |

关闭垂直同步后仍复现卡顿。第二工位两个系统采样点的换页读取为零，房主该段的帧间隔中位数仍有 463 ms。垂直同步开关只用于隔离变量，正式 Mod 未改显示选项。

### 同一镜头暂停联机更新

运行 `steam-dual-0ba974df1fa4466498688171a6da4461`。两端打开垂直同步，镜头全程固定在冷藏箱。房主三段依次正常更新、暂停联机 Pump 12 秒、恢复更新。Unity 模拟与两个窗口保持运行。中段房主只测到 1 次到期后的 Pump，客机 Pump p95 从前段 11.43 ms 降到 0.22 ms。

| 房主状态 | 模拟秒 / 采样墙钟秒 | 帧间隔 p50 / p95（ms） |
|---|---:|---:|
| 正常更新 | 2.125 / 12.003 | 486.19 / 725.65 |
| 暂停联机 Pump | 2.438 / 12.006 | 440.76 / 497.50 |
| 恢复更新 | 3.250 / 12.274 | 450.02 / 494.21 |

暂停期间仍有约半秒一帧的停顿，恢复后也与中段接近。本轮的双进程运行问题在房主停止处理联机数据时仍可复现。系统内存、游戏渲染和其他线程的时间还需分开观测。按用户选择，常规回归转到 148 周期档，1160 周期档继续保留作大图压力样本。

## 复测

先用双 Steam 脚本准备有隔离存档路径的游戏副本。运行下面的观测脚本时，`GameCopy` 指向一次真实双 Steam 运行生成的 `host-game`。每段结果与原始截图留在新建的 `artifacts/qa/map01-*` 目录。日志里的 `PASS MAP01_*` 表示采集完成，实际推进和异常列用于判定运行状态。

~~~powershell
$map = @{
    SavePath = '.\artifacts\qa\mature-range\Impenetrable-Spacerock-1160.sav'
    GameCopy = '.\artifacts\qa\steam-dual-13265e7963c54d71adffb06b2306b084\host-game'
}
$package = '.\dist\QueyangCoop-0.3.2-large-map-join-preview.zip'
.\tests\Integration\Performance\map-baseline.ps1 @map
.\tests\Integration\Performance\map-baseline.ps1 @map -Mode idle -PackagePath $package
.\tests\Integration\Performance\map-baseline.ps1 @map -Mode host -PackagePath $package
~~~

复现或验证旧任务恢复问题时，在空房调用后加 `-CaptureJoinSnapshot`。旧包的暖机对照另加 `-WarmupBeforeCaptureSeconds 12`。

双端在成功入房后测三段运行样本，使用 `steam-dual.ps1 -CheckColonyJoin -CheckColonyRun`。即使采集通过，也须基于报告中的 `MAP01_DUAL_STAGE`、游戏错误及场景状态验收。大图只测两次暂停入房时继续用 `-CheckColonyJoin`。

显示对照额外传 `-Map01VSyncOff`。录像另开一轮，传 `-Map01Video`，主客机各输出一段 24 秒真实窗口采集，避免编码负载混入性能基线。联机更新诊断传 `-Map01PumpControl`，三段固定同一工位，中段房主测试夹具短暂跳过联机 Pump 后自动恢复。
