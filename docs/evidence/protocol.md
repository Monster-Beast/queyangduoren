# 当前实现的协议与范围

v1.0 共用同一个 Core 程序集，由游戏适配层传入发送、断开、主线程采集、执行和单调时钟。Steam 连接和开发 TCP 都承载完整 QYMP 包。TCP 的外层增加 4 字节小端长度；Steam 保留消息边界。线格式的可执行定义在 src/Core/Wire.cs、RoomHost.cs 和 RoomClient.cs；固定字节样本由 RoomTests 验证。

| 项目 | 当前实现 |
|---|---|
| 帧 | ASCII QYMP，u16 主次版本、类型、标志，i32 负载长度。总长 ≤ 64 KiB。枚举依次从 1 开始，见 Message。命令文本字段为 u16 字节长度和严格 UTF-8，≤ 1024 字节；结果字段最多 8192 字节，管理菜单在结果里携带有界的选择项。 |
| 连接身份 | Hello/Reject 只带文本。成功后，所有帧带 16 字节新房间 GUID 和主机分配的正 i32 连接代。主机读档后重新开房使用新 GUID。房间内每个新连接使用新编号。识别 Steam 成员在传输层完成。 |
| 兼容 | Vanilla 和启用 Mod 清单先在本机校验。双方交换游戏程序集、游戏适配 DLL 和 Core DLL 的模块版本指纹，指纹相同才能订阅。 |
| 订阅 | 每客机一个可移动的 24×16 格显示区域。代号 u32，自增；重新订阅即撤销旧代待显示数据和待确认的显示基线。初始 (-1,-1) 由房主定位。 |
| 快照 | 房主在主线程提取不可变显示字节串，以该订阅最后一次得到 Applied 的图像为基准。Begin 发送订阅代、起止修订 u64、目标长度、相同前缀/后缀长度和目标 SHA-256；Chunk 只传变化的中间区域。整块替换与增量共用这条路径。每块 ≤ 32 KiB，窗口 8 块。 |
| 应用 | 客机在独立缓冲区合并并验证完整摘要后一次切换显示；回传 Applied 和已处理偏移。每 4 个完整块回报 Window。缺口、坏摘要或错序触发新基线。重新加入总是从新基线开始。 |
| 权威 | 先检查会话、代号与命令序号，再由房主线程调用真实游戏 API。最近 64 个结果可重放；更早的请求按水位拒绝。每连接每秒最多 32 个操作额度，3 秒实时时钟心跳。每个客机独立采样及发送窗口；未认证、长时间无响应或基线卡住会超时。 |
| 时间和时序 | 提交序号用于房主收到的远程命令，修订用于订阅视图。房主玩家继续使用原生输入；对同格建造通过原生占用、尚未注册对象的占位和主线程顺序协调。全局原生游戏 UI 操作没有完整命令日志。 |
| 可观测性 | 每 60 秒在 Player.log 写一行会话角色、pump 耗时 p95、客机命令响应 p95、采样间隔、收发字节/秒；时间数据包含 Mod 会话泵，原生物理与图形渲染需另测。 |

与设计稿相比，首个实作选择每人一个移动视口、每秒最多 4 次一致采样和按连续字节区间发送差异。这些决策使本版能在原版游戏里验证挖通格子、环境变化和同格冲突。独立存档副本开房、掉线重连和晚加入都不需要传送原始 .sav。显示范围、网络与存档可分别测量和升级。
