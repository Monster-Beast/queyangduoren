# 当前实现的协议与范围

v1.0 共用同一个 Core 程序集，由游戏适配层传入发送、断开、主线程采集、执行和单调时钟。Steam 连接和开发 TCP 都承载完整 QYMP 包。TCP 的外层增加 4 字节小端长度；Steam 保留消息边界。线格式的可执行定义在 src/Core/Wire.cs、RoomHost.cs 和 RoomClient.cs；固定字节样本由 RoomTests 验证。

| 项目 | 当前实现 |
|---|---|
| 帧 | ASCII QYMP，u16 主次版本、类型、标志，i32 负载长度。总长 ≤ 64 KiB。枚举依次从 1 开始，见 Message。命令文本字段为 u16 字节长度和严格 UTF-8，≤ 1024 字节；结果字段最多 8192 字节，管理菜单在结果里携带有界的选择项。 |
| 连接身份 | Hello 带构建指纹和可选原生模式标志；Reject 带原因。成功后，所有帧带 16 字节新房间 GUID 和主机分配的正 i32 连接代。主机读档后重新开房使用新 GUID。房间内每个新连接使用新编号。识别 Steam 成员在传输层完成。 |
| 兼容 | Vanilla 和启用 Mod 清单先在本机校验。双方交换游戏程序集、游戏适配 DLL 和 Core DLL 的模块版本指纹，指纹相同才能订阅。 |
| 订阅 | 每客机一个可移动的 24×16 格显示区域。代号 u32，自增；重新订阅即撤销旧代待显示数据和待确认的显示基线。初始 (-1,-1) 由房主定位。 |
| 快照 | 房主在主线程提取不可变显示字节串，以该订阅最后一次得到 Applied 的图像为基准。Begin 发送订阅代、起止修订 u64、目标长度、相同前缀/后缀长度和目标 SHA-256；Chunk 只传变化的中间区域。整块替换与增量共用这条路径。每块 ≤ 32 KiB，窗口 8 块。 |
| 应用 | 客机在独立缓冲区合并并验证完整摘要后一次切换显示；回传 Applied 和已处理偏移。每 4 个完整块回报 Window。缺口、坏摘要或错序触发新基线。重新加入总是从新基线开始。 |
| 权威 | 先检查会话、代号与命令序号，再由房主线程调用真实游戏 API。最近 64 个结果可重放；更早的请求按水位拒绝。每连接每秒最多 32 个操作额度，3 秒实时时钟心跳。每个客机独立采样及发送窗口；未认证、长时间无响应或基线卡住会超时。 |
| 时间和时序 | 提交序号用于房主收到的远程命令，修订用于订阅视图。房主玩家继续使用原生输入；对同格建造通过原生占用、尚未注册对象的占位和主线程顺序协调。全局原生游戏 UI 操作没有完整命令日志。 |
| 可观测性 | 每 60 秒在 Player.log 写一行会话角色、pump 耗时 p95、客机命令响应 p95、采样间隔、收发字节/秒；时间数据包含 Mod 会话泵，原生物理与图形渲染需另测。 |

## 原版场景入房与周边更新

玩家连接会请求一份房主当前的原生存档。房主在游戏线程把世界写入独立临时目录，保持原来的保存目标；接入者在本地随机路径接收不超过 128 MiB 的文件。NativeBegin、NativeChunk、NativeWindow、NativeEnd 使用 32 KiB 分块、最多 8 块在途和 SHA-256 完整性校验。校验成功后发布临时 .sav，客机调用原版加载器。NativeReady 之后开始视图增量。存档包含完整殖民地数据，适用于受信好友。

每个连接独立维护中心订阅；原版镜头缩小时，PeripheralRequest/PeripheralChunk 另行补发可见周边。每人同一时刻最多请求一块，房主限制为每秒最多 8 块；周边数据不改变主订阅代或阻塞下单。游戏时钟冻结期间会话仍使用单调时钟运行。原版 UI 的已接入操作由房主按当前资源、可见性、对象身份和旧值验证。具体实现和证据见[原版客机验收](native.md)。

### 视区版本与边界

单个解码后视区固定为 24×16 格。v4 保留诊断画面，v5 增加原生标识和动画，v6 增加管网与材质，v7 增加分页库存、矿堆和建筑存档标识。读取这些版本时，`HasEnvironment` 为假，`EntityPayload` 为空引用。i32 的房间目标代号用于验证远程写入，原版存档对象 ID 用于将接收到的状态对应到客机已载入的对象。

v8 的 u16 版本号后有一个扩展标志字节。低两位分别表示环境与实体。主体沿用 v7，环境段在库存后，最后是实体长度 u16 和最多 8192 字节的实体数据。环境只为已揭示的格子编码。每格的掩码标记病菌、照度、装饰、运输轨道、气管病菌、液管病菌及建筑锚点病菌。轨道传递连接方向、载货标识和质量，病菌以 i32 数量和 u8 种类表示。库存物堆的病菌数据跟随环境格列表发送。

发送端先尝试发送完整视区。超过 65520 字节时可使用有界 gzip，外层依次为 u16 版本 8、标记 128、i32 解压长度、i32 压缩长度和压缩数据。最多解压 160 KiB，仅接受一层封装。高度不可压缩的视区改用缩短的显示名称，并按四个连续的 96 格范围轮换环境读数。环境段首字节取 0 表示覆盖全部，取 1 到 4 表示对应范围。客机通过 `CoversEnvironment` 判断哪些值可以覆盖，未覆盖的格子保留上次读数。每一页都完整保留当次的实体区段和库存页。

每条新连接领取独立的房间内连接代，即使传输层复用相同句柄。已核验的中心视图和周边视图在同一条可靠通道中按完成顺序交给画面层。切换订阅后，客机消费旧周边响应的剩余字节并释放请求槽，不会将其应用到新镜头。命令缓存可向重试者重发结果，客机只向 UI 派发仍待完成的命令一次。对应边界可运行 `dotnet test tests/Core.Tests/Core.Tests.csproj -c Release`。

每格环境掩码的最高位表示可识别的原版房间，置位时按顺序传送三个 i32，分别为非零房型哈希、非负锚点格编号和大于零的房间格数。此位为零时，当前覆盖格的房间记录清空。房主收到同代重复或滞后的累计窗口确认时保留已确认进度。请求重发命令结果也会消耗该连接的输入额度。客机读完原生存档并发出 NativeReady 后，房主还需收到首个视图区的 Applied 才能执行写命令。

视图扩展标志的第 2 位（数值 4）表示订单状态。此段在环境、实体载荷之后，每个可见格一个字节。低四位取 0（无）或 1–9 的优先级，第 4 位（数值 16）为擦地订单。第 5 位（数值 32）表示同格另有独立订单目标，紧接正 i32 订单标识和 u8 优先级（0–9）。主建筑和订单各自保留操作标识与优先级。如果满页高熵双目标超过字节预算，发送端可省略显示标签并保留数值。整张视图都没有状态时省略此段，解码为全部清空。即使环境按 96 格分页，订单状态仍覆盖整张视图。每条连接的中心采样与每个外围请求坐标分别递增取样序号。环境、库存、物堆、实体分别按各自的总页数取模。房主的其他客机或外围采样不会消耗本中心的页号。

v8 的 `EntityPayload` 使用独立的实体子协议 v3，兼读 v1 和 v2。每页最多 52 个稳定实体 ID，每实体最多六种材料分类。穿戴物品（Item、Carried、Flags 含 32）在 Flags 后额外携带 i32 WearBuild、u8 packedLen 和 packedLen 个字节。WearBuild 为实际服装资源名称的哈希，含外观替换。packedLen 最多为 64，每字节记录四个本地 build 的符号，最多 256 个。每个符号占两位，0 为无覆盖，1 为隐藏，2 为显示，3 为非法。客机通过 SymbolOverride 叠加和撤销外观，装备差事仍由房主执行。

## 原版管理面板的全局数据

客机打开研究窗口或建造分类时请求 `nm/research`。收到新完成科技时，客机把完成标志和研究进度应用到临时世界，并通知原版建造菜单更新解锁类别。打开排班或优先级窗口时请求 `nm/schedules/页码`。每页最多两张排班表，返回房主进程内稳定编号、名称、闹钟、仿生人默认标志和时段。目录版本涵盖编号、顺序、名称、闹钟及行数。收完同一目录版本后再应用增删、重命名与顺序。时段和成员读数对应各自采样时刻。当前上限为 2048 张排班表、每表 2048 个时段、名称最多 512 UTF-8 字节。

原版客机按 Esc 打开联机菜单，再点「殖民地概览」时请求 `nm/overview`。房主从当前世界的 RationTracker 读取食物热量，从 NotificationManager 读取整个殖民地当前活动的 BadMinor、Bad、DuplicantThreatening 三种警报，列出总数及最多八种标题。同标题显示合计数量。每次读取替换面板文本，重连清理订阅；此路径没有向原版提醒管理器注册通知。房主隔离档夹具 `NativeManagementChecks` 校验目录增删、改名、多行和热量。双端画面仍需分别在真实 Unity 的对应面板核验。
