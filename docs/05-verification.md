# 环境、验收、打包与回滚

## 从干净工作区开始

下面第一组可在文档阶段执行。后续标明“实施后”的路径是开发任务的交付合同。示例在 Windows PowerShell 运行。验证模板中的通过条件都是目标，真实结果写到 docs/evidence/。

**1. 确认仓库与工具链。** 从仓库根目录运行，预期 origin 对应目标仓库，能看到 SDK 版本。这样能先定位是仓库、SDK 还是游戏依赖缺失。

~~~powershell
git remote get-url origin
git status --short --branch
dotnet --list-sdks
~~~

**2. 确认游戏和程序集。** 在 Steam 的游戏属性中浏览《缺氧》的已安装文件，将实际目录填入下面路径。预期 DLL 存在，SHA-256 可与另一台机器对比。build 编号另从游戏标题界面或 Player.log 记录；程序集哈希不等同于 build 编号。另记录启用的 DLC、Mod 和 Steam 绑定/Harmony DLL 版本。

~~~powershell
$env:ONI_GAME_DIR = 'D:\SteamLibrary\steamapps\common\OxygenNotIncluded'
$managedDir = Join-Path $env:ONI_GAME_DIR 'OxygenNotIncluded_Data\Managed'
Get-FileHash -LiteralPath (Join-Path $managedDir 'Assembly-CSharp.dll') -Algorithm SHA256
Get-ChildItem -LiteralPath $managedDir -File | Where-Object { $_.Name -match 'Harmony|Steamworks|UnityEngine.CoreModule' } | Select-Object Name,Length
~~~

找不到 DLL 时先检查 Steam 库位置和游戏安装，命令须指向游戏目录。实施时支持环境变量或忽略版本控制的本地 props；在缺 DLL 时输出缺少的具体文件及纯核心测试入口。依赖游戏组件作本地引用并设置不复制。net48 targeting pack 或相应引用程序集需要在 CI/构建机单独配置。

**3. 建立环境检查和分层构建（实施后）。** 要求子 agent 提供这些入口；脚本解析仓库相对路径、传递正确退出码。doctor 列出 SDK、游戏 build/库、目标框架和环境缺项。纯核心测试应可在没有 Steam 的机器运行，恢复 NuGet 需网络或已有缓存。

~~~powershell
.\tools\doctor.ps1
dotnet test .\tests\Core.Tests\Core.Tests.csproj -c Release
~~~

在已装游戏的机器编译并打包。预期构建没有未解析的游戏引用，包内有本 Mod DLL、mod.yaml、mod_info.yaml 和明确允许随包的运行依赖/许可。未能验证当前 build 时不要在元数据中宣称支持。

~~~powershell
dotnet build .\QueyangDuoren.sln -c Release
.\tools\package.ps1 -Configuration Release
~~~

**4. 安装到独立 dev Mod 目录。** 安装脚本支持 PowerShell -WhatIf，默认目标独占且检测工坊或 Local 中同一 Mod ID 重复。先在复制的测试存档中启用。实际覆盖既有 dev 包前提示变更，备份目录并返回备份位置；删除或回滚前校验规范化路径。预期单人入口仍能正常开局，菜单中出现“开设合作房间”和“加入房间”。

~~~powershell
.\tools\install-dev.ps1 -WhatIf
.\tools\install-dev.ps1
~~~

## 测试层和最小回归集

| ID | 环境与动作 | 预期及证据 |
|---|---|---|
| T01 协议 | 无游戏 CI。固定字节样本双向解码，未知版本、超长帧、截断、乱序/重复回调、非有限数、异常数组长度 | v1 字节稳定；错误可读且内存有界；无状态半应用 |
| T02 并发 | 假游戏适配器。三人同时提交重叠建造/取消，重送、过期、跨 epoch 重放；暂停中继续发命令 | 全局提交有序，成功对象只创建一次；失败原因可验证，已执行请求永不重放 |
| T03 初始与增量 | 内存传输。大于 10 MiB 的合成基线，传输时世界持续变化；切视口，注入缺口、重复块、坏哈希与跨代迟到包 | 完整校验后原子可见；补发/重取后同一水位摘要一致；中途退出释放缓冲 |
| T04 客机隔离 | 两个游戏实例。移动镜头、选区、建梯、挖通密闭气室，交替暂停/恢复，观察两个计数器和侧栏 | 房主计算 AI/物理，客机对应计数为零。格子、复制人、气体与 tooltip 随权威状态变化；客机本地存档时间戳未变 |
| T05 玩法矩阵 | 真机。逐行执行功能表，用两个玩家并发改同一目标，然后换视口、晚加入、拆除选中物体 | 操作结果和 UI 一致，跨区域状态正确，所有开放的客机写入口均能映射到登记能力 |
| T06 网络故障 | 自动用例模拟 RTT 150 ms、2% 可丢包丢失、乱序、拥塞、断开/恢复。可靠流通过延迟/断连模拟重传影响。房主加两客机，让一端降速 | 健康端继续运行；慢端补进度或明确重连；最终摘要一致。固定随机种子能复现 |
| T07 真实 Steam | 两个独立 Steam 账号/环境，记录游戏和 Mod build。从游戏内好友邀请加入，检查拒绝不匹配版本、退房、房间满、重新邀请 | 真房间、真 P2P、双方不同视角操作；记录连接路径/错误和实际在线人数。回环成功不能代替此项 |
| T08 四人及长稳 | 四个 Steam 玩家，在不同区域施工；两人同时回房；连续运行至少 60 分钟，覆盖保存、快进和中途离开 | 四人均操作成功；无异常退出、未恢复分歧或持久队列增长；销毁的实体/会话资源计数回落 |
| T09 存档与单人 | 用 Vanilla 新档和一个发展中/后期存档的副本开房；跨自动保存、手动保存、重开，禁用 Mod 后单人加载。客机离开再进单人，重复三轮 | 原生档可载入，房主重开后状态正确，客机本地档无覆盖；无残留补丁副作用、幽灵实体或重复回调 |
| T10 发布包 | 干净 dev/Local 安装位置，用生成的压缩包构建同一 Steam 双人局；检查清单、哈希和版本 | 能从菜单开房、入房、施工、重连；包内无游戏 DLL、存档、个人路径、SDK 凭据 |
| T11 数据与过载 | 提交越界坐标、未知 prefab、过期实体、大批重复操作；在基线阶段发命令，尝试非房主暂停 | 只影响发起者；世界不变；给明确定义的拒绝码，无分配失控。正常玩家可继续操作 |

T04/T05 的玩家版验收要求两台独立安装《缺氧》的设备同时进入原版殖民地场景。分别录下两人独立移动原生镜头、切换原版叠层、查看侧栏和用原版工具下单的过程，同时比对房主执行与客机隔离计数。

## 可比的性能预算

先记录硬件、游戏 build、存档周期、复制人数、可见网格数、倍速、分辨率、场景持续时间和同存档单人基线。原型验收采用同机同档对照。建议首版起始目标如下，若确有硬件/规模原因无法达到，应记录实测、瓶颈、改动和替代门槛并保留原目标差距。

- 普通施工场景以 1 倍速各测 10 分钟。房主 Mod 自身每帧主线程耗时 p95 ≤ 4 ms；记录房主模拟步/秒相对单人下降比例，起始门槛 ≤ 15%。区分快照采集与日常增量时段。
- 记录从点击到收到房主确认的 p50/p95；局域网 p95 目标 ≤ 200 ms，故障模拟场景 p95 ≤ 750 ms。和复制人完成施工的时间分别计量。
- 在固定视口和场景记录每客机字节/秒、可靠积压和全量重取次数；1 倍速普通施工平均下行先以 ≤ 2 MiB/s 为目标。开发 LAN 用 20 Mbit/s 可用链路和 10 MiB 基线，晚加入到 Live 目标 ≤ 15 秒。Steam 单独报告网络与耗时。
- 长稳每分钟取一次按范围对齐的权威摘要、队列、GC、内存和客户端水位。完成追赶后结构性差异为零。即使 demo 流畅，也需检查真实大殖民地的步速、基线峰值和晚加入时间。
- 留存机器可读指标、时间区间与测试 commit；无法自动采集的项目以手工操作脚本、两端日志和实际观察补充。保存用于对照的匿名日志片段，不上传他人的完整存档或账号标识。

## 故障定位与回滚

| 现象 | 首先检查 | 最小恢复 |
|---|---|---|
| 游戏启动即报错 | 实际 build、Harmony 重载数量、游戏引用和包内是否出现重复 DLL | 禁用该 dev 包，恢复备份，验证原版单人；修正失配能力后重试 |
| 能进 Lobby 但无法进入世界 | 双方的 Hello/Reject、Steam 回调、基线字节进度、hash 与 ACK | 按阶段显示故障，清理半开会话，重进；分别验证回环和 Steam |
| 同一格/建筑显示不一致 | session/epoch、订阅代、水位、删除事件、区域摘要、首个差异字段 | 先请求该范围基线；日志溢出时进行完整显示状态重建 |
| 房主卡顿 | 分开观察采集、拷贝、编码、压缩和发送队列；与纯单人对照 | 减小订阅、分帧采集、降低非关键层采样，保持一致快照及可靠提交 |
| 客机仍会自主扣料或移动复制人 | 双端角色、客机模拟计数、输入重入、代理组件和读写来源 | 禁用出问题的客机写入口，修复角色隔离或改用只读适配器，再重跑 T04/T05 |

安装/回滚脚本要能在相同参数下重复运行。游戏退出后再替换 Mod 文件。操作原存档前先复制到测试位置；记录副本路径和文件哈希。示例在设置真实路径后执行，备份名带时间戳，避免覆盖已有副本。

~~~powershell
$sourceSave = Read-Host '输入测试用原始 .sav 文件完整路径'
$backupSave = "$sourceSave.$(Get-Date -Format yyyyMMdd-HHmmss).bak"
Copy-Item -LiteralPath $sourceSave -Destination $backupSave -ErrorAction Stop
(Get-FileHash -LiteralPath $sourceSave).Hash -eq (Get-FileHash -LiteralPath $backupSave).Hash
~~~

预期为 True。要恢复时，在游戏已退出的情况下将备份复制为一个**新名称**的 .sav，单人菜单从该文件加载验证；保留故障现场供诊断。Mod 包回滚先在菜单禁用本版本，再运行实施阶段交付的 restore-dev.ps1 -BackupPath 指定备份，支持 -WhatIf。首次安装无旧包时，禁用即可恢复单人工作流。

## 发布判定

主 agent 输出 commit、支持的游戏 build 与内容包、包版本/SHA-256、能力表、T01–T11 状态和证据、性能数据及剩余限制。状态限定为“通过/失败/待环境验证”，如失败需给最短复现。自动化通过但缺双机实测时可交付候选包；实机项通过后才能标记已验收。向 Steam Workshop 公开上传属于单独的发布动作。
