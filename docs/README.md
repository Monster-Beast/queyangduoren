# 《缺氧》同图合作 Mod 开发总纲

当前开发包为 0.2.0-dev，适配 Windows Steam 基础版《缺氧》Klei 744825。房主推进殖民地，每个客机用自己的游戏加载房主当前的存档副本。安装、开房和加入步骤见[仓库首页](../README.md)，可运行范围、截图与分项结果见[原版客机实测](evidence/native.md)。下列设计文档保留项目的开发目标与正式版验收条件。

**交给 Codex 开工**：打开 [长任务委托书](06-codex.md)，复制“可直接发送的委托”全文。主 agent 持有集成和验收责任，先跑环境检查，再组织子 agent。无需人工逐章派工。按 [验证与发布](05-verification.md) 区分代码交付、游戏实测和可发布状态。

## 首版的玩家体验

房主从原版新游戏或已有的单人存档副本开局，通过 Steam 邀请好友。同一颗小行星上，每个人有独立的镜头、选区和工具，能同时在不同位置工作。殖民地资源、复制人、日程、研究和游戏时钟共享。房主负责暂停、倍速、保存和结束房间；客机掉线时殖民地继续运行。好友回来后从房主取得当前视图。房主退出后大家回到菜单，可由原房主重新读档开房。

建议把 Windows Steam、Vanilla 单星体、2–4 人（含房主）、相同游戏构建与 Mod 版本定为本次工程边界。最小原型先做 2 人，正式交付需验证 4 人。运行条件默认仅启用本 Mod 和必要依赖。DLC、多星体、第三方内容 Mod、主机迁移、无人值守服和工坊公开发布留作单独任务。这些是便于估算及验收的首版选择，可在开工前显式调整。

## 项目级成功条件

1. 原版游戏进程里只有房主驱动权威殖民地。客机写操作可追溯到房主确认的唯一结果，单人模式继续使用原生路径。
2. 从邀请、加入到独立操作构成一次完整会话。两人能异地挖掘、建梯子、取消重叠命令；可看到复制人施工、资源和环境的实际变化。
3. [玩法能力表](04-delivery.md) 中列为正式版的功能有对应的实现和证据。未接入的写操作在客机明确显示原因，不得静默执行或假装成功。
4. 晚加入、重连、大地图传输、房主保存与重开、连续运行和版本不符均有可复现结果。玩法里程碑不能仅凭编译通过或模拟器截图验收。
5. 交付包含可复现构建、干净的 Mod 安装包、测试记录、已知限制和回滚方法。缺双机环境时，主 agent 完成可独立验证的所有任务，报告精确剩余步骤，保持实机门槛待验。

## 优先解决的不确定性

最贵的未知项是 ONI 客机失去本地物理、AI 和任务驱动后，哪些原生界面还能正确工作。先做一个真实的挖掘闭环并记录补丁与读数。若原生地图依赖不可拆分的模拟，保留房主唯一权威，在游戏进程内用只读地图视图和自有工具适配器继续验证。简化视图只算网络原型。玩家版要求每个人都在自己安装的《缺氧》中看到原版殖民地、复制人动画、叠层和操作界面，两个玩家可以独立移动镜头。
