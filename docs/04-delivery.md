# 功能清单和里程碑

## 玩法能力表

“正式版”指本计划的 Vanilla 合作首版。对每个开放入口建立能力登记表，至少记录 operationId、主机原生入口、客户端读取来源、权限、失败反馈、测试 ID 和已测 build。尚未完成的写入口在客机禁用并提示“此版本仅房主可操作”，保证任何可点击操作都有可解释的结果。首版接受房主代办表内明确列出的低频操作。

| 功能 | 原型 P1 | 首版范围和验证例子 |
|---|---|---|
| 玩家会话 | 回环或 LAN，两端角色隔离 | Steam 好友房、2–4 人、晚加入、重连、掉线提示、版本拒绝、结束房间。两名客机在不同视口同时操作。 |
| 视角与时间 | 双镜头、独立选择、房主时钟 | 独立平移缩放、工具选择、面板、叠层，房主暂停/继续/改速，客机显示时间和暂停原因。暂停仍可规划。 |
| 格子工具 | 单格/框选挖掘，观察完工 | 挖掘、取消、拆除、扫除、擦地、收获、优先级。框选跨边界、取消别人已取消的对象、有部分无效目标时均反馈。 |
| 建造 | 先一格梯子 | 基础建筑实例覆盖梯子、砖块、门、储物箱、供氧和发电设备，覆盖拖线的电线和气液管。检验原生朝向、材料和层重叠；其余 prefab 按已验证通用能力/白名单开放。 |
| 复制人及资源 | 看得到执行挖掘及掉落 | 展示位置、活动、施工阶段、可用资源；修改优先级、排班。测两个工地争用最后一份材料。客机只提交计划，不自行扣料。 |
| 环境与网络 | 固体变空气，温度与质量 tooltip | 可见气液、温度、氧气叠层、电力和管道拓扑/读数，关键建筑和自动化信号状态。用密闭房间开口、跨镜头管路、断电恢复验证。 |
| 建筑与殖民地管理 | 一个建筑状态侧栏 | 建筑启停、储物过滤、设备配方队列、研究队列、共享资源摘要。有并发编辑的属性带条件版本。测试修改后换镜头、重连仍一致。 |
| 低频或专门面板 | 房主原生交互 | 打印舱选人、技能分配、复杂自动化参数、航天及未登记的特殊建筑设置先由房主代办，相关可见状态按已支持字段同步。分别记入发行说明。 |
| 持久化 | 单人存档副本开房 | 房主原生手动/自动保存、退出重开、卸载 Mod 后用测试存档回到单人。客机机器不覆盖本地殖民地。 |
| 兼容边界 | 验证一组真实 build | Vanilla 同 build、相同协议及受支持 Mod 清单。DLC 和影响模拟的第三方 Mod 组合明确拒绝并指出差异。多星体后续按 worldId 扩展。 |

## 阶段及依赖

| 阶段 | 输入与可并行工作 | 必须交付 | 退出条件 |
|---|---|---|---|
| P0 工程与证据 | 空仓库；环境盘点、上游 API 调研、纯协议样本可并行 | 工程布局、构建锁、环境检测、角色生命周期探针、版本指纹、最小 Mod 加载 | 纯核心可独立构建；有游戏时本机载入并退回单人，记录补丁签名；缺游戏时相应门槛保持待验 |
| P1 单房主纵向原型 | P0 接口；传输先用回环/LAN | 一条从客机到房主再到视图的真实挖掘命令，一条梯子建造流程，主客 tick 计数，显示路径选择记录 | 两个游戏实例均以原版场景、镜头、工具和侧栏独立操作，开挖后复制人和气体均变化。双方争同格只产生一个计划，客机停算仍能查看/下令 |
| P2 复制和会话 | P0 数据合同，P1 选定显示适配器 | 分区采集、实体寿命、可靠提交、初始快照、增量、晚加入、重连、背压，Steam 邀请与角色握手 | 故障测试全过；主机保存不迫使全员重载；慢客机不阻塞其他人；真实 Steam 双账号建立连接 |
| P3 玩法覆盖 | P1、P2；独立功能组按各自入口分工 | 完成上表首版各项，维护能力清单和客机面板禁用规则 | 每个启用功能有绑定、结果、重连后读数及测试。互斥操作、暂停中输入、资源竞争均可复现 |
| P4 实测、性能、打包 | 各块独立测试可提前，完整会话需 P3 | 2/4 人记录、原版回归、长稳与大基线结果、可安装包、符号/日志指南、版本和限制 | 达到验证文档门槛；发布包在干净安装目录走真实入口通过，不含游戏程序集 |
| P5 兼容迭代（后续） | 首版证据与用户反馈 | 另行选择新增 DLC、更多面板、第三方 Mod、平台或专服 | 每次只扩展已测矩阵，并补充对应存档和回归案例 |

依赖关键路径为“游戏 DLL 与测试存档 → 确认模拟/渲染分离 → 真实挖掘闭环 → 多子系统复制 → 双机及四人验收”。协议、故障模拟、构建工具与 Steam 接口探针可以提前开始。原版呈现受阻时提交日志和最小复现，定位场景对本地模拟的依赖，继续验证原生读取入口。自绘地图只用于诊断。不得转用双端独立运行模拟来勾选 P1。

## 开发交接清单

每个阶段在 docs/evidence/ 追加一条记录。格式为「日期 / commit / build / 环境 / 变更 / 实际执行命令 / 实测与预期 / 原始日志或 CI 链接 / 待验条件 / 下一责任人」。没有设备的场景可提交可运行用例和脚本，状态写“等待实机”；日志与截图标注来源。主 agent 每轮选一项真实集成行为操作，及早发现只在模拟接口说得通的设计。
