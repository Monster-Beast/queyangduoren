# Codex 长任务委托书

## 玩家画面的验收要求（2026-11-22 更新）

房主和客机都应看到《缺氧》原版殖民地画面，各自移动镜头，用原版工具和侧栏操作同一座殖民地。0.1.0 历史开发包的客机使用 24×16 自绘面板，只作为协议、命令及单房主模拟的验证工具。玩家版验收以双方的原版场景和原版操作为准。

后续先做一个原生画面的端到端实验：选取同一片已揭示区域，分别录制房主和客机的地形、建筑与复制人动画；把两个镜头移到不同位置，在客机用原版挖掘工具提交订单，观察复制人实际完工和两端画面更新，并记录客机模拟、任务和写档计数。实验需验证原生渲染、动画和工具依赖哪些本地世界状态。原版客户端的当前进度、实机证据及余项见 docs/evidence/native.md。通过这一条路径后，再扩展建筑、管线叠层与管理侧栏。

## 可直接发送的委托

把下面整个文本块作为一次任务发给主 Codex。可先打开项目工作区，再发送委托。

~~~text

这是一项从当前仓库持续做到首版交付的实施任务。请作为主集成者，明确使用子 agent 并行开发。先只读检查分支、用户已有改动、AGENTS.md、实际游戏安装/程序集、SDK 与测试设备。遵守本仓库说明，保留用户改动。在独立实现分支上工作。直接推进所有已授权且可做的工作，无需逐阶段向我确认。不要向创意工坊上传或覆盖玩家原档。实现中发现设计与真实 API 不符时，用可复现实验修订对应合同和测试，再继续集成。

先定 core 类型、线协议、项目和测试入口，再按本页的写入边界派工；实际并发槽位不足时顺延。优先打通原生游戏中的“客机挖一格、房主执行、两边看到小人完工和气体变化”。证明客机停跑权威模拟且仍能看图和下令；每位玩家都在自己安装的游戏内使用原版殖民地场景、镜头、动画、叠层、工具和侧栏。原生视图受阻时记录依赖并修复，自绘面板只用于网络诊断。完整任务还包括玩法能力表、Steam 房间、版本检查、重连、大快照、冲突、诊断、存档回归、打包及说明，做通原型后继续 P2–P4。

每个子任务都需提交改动文件、执行命令、结果和具体缺口。你负责合并、检查、重跑测试并走玩家入口。不要用 mock、空方法、打印日志、单机截图或设计稿充当真实游戏集成完成的证据。缺游戏 DLL/账号/设备时，先完成所有与该条件独立的实现和测试，交付可运行的检查脚本与剩余实测步骤。不可验证的签名只能登记为候选，接口替身仅限测试工程。不要上传商业游戏 DLL 或从非授权来源补 DLL。

把当前进度、接口版本、提交、实测证据、技术决定、待办和下一条命令放进 docs/evidence/，让下一次会话可以续跑。按 docs/05-verification.md 对 T01–T11 和性能预算逐项给出真实状态。最终交付源码、可复现构建、候选发布包（构建环境允许时）、安装/回滚和证据索引。总结已通过、失败和待验项，明确哪一个条件仍阻止正式验收。
~~~

## 主 agent 的启动顺序

1. 读 docs/README.md → 01–05，检查当前仓库分支和现有工作；已有实现时先对照当前状态继续，避免重复开工程。建立 docs/evidence/status.md，记录起始 SHA、角色、已知资源与测试环境。
2. 建好解决方案、基础类型和所需项目引用，仓库根构建文件、打包清单和共享注册表由主 agent 或单一指定集成者维护。冻结第一版术语、DTO、消息号、序列化合同、错误码和测试样本。
3. 将下表作为任务池。每个任务明确输入、可写目录、兼容合同、可重跑命令和输出，告诉子 agent 其余目录的负责者。同一工作区并发时使用互斥目录；复杂合并可用独立 worktree。先为每个子 agent 分配一个不相交的测试子目录。
4. 每完成一条端到端路径即集成一次。合并前审查共享文件差异和真实游戏线程访问；合并后用当前 HEAD 重跑前一阶段的回归。发生冲突由主 agent 仲裁合同、更改版本与样本，再通知消费者。
5. 长运行或上下文切换前写入实际命令、最后一次绿色构建、失败证据、当前分支、未提交变更位置、下一个验收项。恢复后用 git status、git log、状态页和证据定位断点。

## 子 agent 工单

每行是一张可独立分派的工单，负责者可以在同一会话依次领取多张。假定最多有主 agent 与 3 个子 agent 时，先 A/B/C，再 D/E/F；主 agent 持续维护集成与设备测试。

| 工单 | 依赖与写入边界 | 产出与移交标准 |
|---|---|---|
| A 协议/复制 | 冻结核心合同后，src/Protocol、tests/Core.Tests/Protocol | 字节规范和固定样本、分块/水位、补发/摘要、上限与异常测试，T01/T03 自测。向 B/D/E 提供可运行的内存往返样本。 |
| B 房主和 ONI 探针 | P0；src/Game/Host、src/Game/Compatibility、tests/Game/Host | 游戏 build/补丁清单、主机命令执行、线程调度、格子/实体一致采集、主机保存与卸载。向 C 给一条挖掘命令和小区域快照，记录真实来源。 |
| C 客机隔离与视图 | 核心合同；src/Game/Client、tests/Game/Client | 原版游戏场景与只读世界数据接入、客机推进计数、输入预览；与 B 合做 P1。提交两条显示路径取舍及实机证据/待验条件。 |
| D 网络与 Steam | A 的帧/握手；src/Transport、src/Game/Steam、tests/Core.Tests/Transport | 内存/开发 LAN、Steam 房间/邀请/连接状态、异常释放、重连、限流。提供回环与真实 Steam 操作步骤。 |
| E 玩法与工具 | P1、B/C 的扩展点；src/Game/Features、tests/Game/Features | 工具/建筑/管理/叠层能力登记及功能测试。按功能垂直切片提交，集成房主执行和客机 UI；新消息号由主 agent 分配。 |
| F 测试、性能、打包 | A 的样本；tools、tests/Integration、docs/evidence/qa | 建 doctor、故障注入与回放、性能记录、包白名单、install/restore、真机用例与对账结果。测试证据区分模拟与真机。 |

主 agent 负责 src/Core、src/Game 入口/角色注册、解决方案/构建文件、CI、功能注册总表与 docs/evidence/status.md。纯核心 CI 从 tests/Core.Tests/Core.Tests.csproj 运行，纳入协议/传输测试并单独执行集成测试工程；游戏相关测试运行条件和失败返回码在实施后补齐。发布清单由 F 提案，主 agent 集成。无并发工具时按同样依赖顺序顺序实现，保留任务边界。一个模块被硬件条件阻塞时，其余工单继续。

## 先冻结的接口语义

以下名字是建议，职责和验收合同优先。主 agent 在派工前统一最终签名和 sample fixture。

| 合同 | 生产者 → 消费者 | 约束 |
|---|---|---|
| ICommandExecutor、CommandRequest、CommandResult | 游戏线程上的房主 → 输入/协议/测试 | 含身份代、目标前置条件和可关联提交序号；只允许已注册的语义操作 |
| IWorldSnapshotSource、WorldDelta | 房主 → 复制层 | 返回一致水位的不可变数据；读取游戏对象限制在合法线程，拒绝跨线程保留原生引用 |
| IReplicaStore、IWorldView | 复制层 → 客机视图 | 基线原子替换，连续批量应用，按订阅读取；禁止通过显示适配器回写房主 |
| ITransport、IConnection、IClock | Steam/LAN/回环 → 会话层 | 连接身份、可靠性、可取消和断线原因；上层不依赖 Steam 类型；单调网络时钟可替换测试 |
| ICapabilityRegistry、ICompatibilityProbe | 游戏适配器 → 握手/UI/诊断 | build、角色、动作、权限与已验证补丁表可查询；游戏更新时精确指出失配项 |

## 每次合并都做的检查

- 检查游戏线程、对象生命周期、退房清理和重试边界；至少运行本次功能对应的核心/集成测试。每轮至少合并一个可观察的行为，例如「接受建造命令后房主只登记一次」。
- 向上一轮对照单人、房主、客机三种角色。对于需人工操作的游戏流程，附精确入口、环境、期望与已观察结果。失败时记录根因、最小修复和回归用例。
- 单人原档、公开发布、共享分支强推均不属于这次实施的默认动作。测试用副本、独立工作分支和本地候选包即可完成工程验收。
- 交付清单逐项对照 P0–P4、功能表、T01–T11、性能预算。发现真实外部依赖且可执行任务已耗尽时，交付当前可复现结果、受影响的门槛及解除依赖后的第一条命令。
