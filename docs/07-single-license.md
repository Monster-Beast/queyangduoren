# 单份《缺氧》授权下的开发与验收计划

基线为提交 `aa6f488`、0.2.0-dev、Windows Steam 基础版 Klei 744825。本阶段只需一份游戏授权，每次运行一个真实游戏进程。目标是让好友加入后，**用于决策的画面和读数、操作结果、退出再加入后的状态**都能追溯到同一个房主。本文列出待开发与待补证的内容。已有实现和实测分别见[原版客机验收](evidence/native.md)和[一小时长稳](evidence/qa/native-soak.md)。

- 房主实际执行挖掘、建梯已有证据。原生客机分阶段实测过镜头、温度叠层、选择、挖掘及梯子拆除/撤销。研究、排班、优先级和建筑启停已在真实房主检查，仓储、配方等仍需逐控件取证。复制人差事详情有已知模板文字问题。[客机实测入口](../tests/Integration/Game/NativeScenario.cs) · [管理同步](../src/Game/Management/NativeManagement.cs)
- 已有一个真实房主与三个协议端连续一小时的结果。下表将“已接入、补行为测试”和“新增实时同步”分别写明；原始存档能加载某个对象，只证明入房时可见。

## 同步语义先定下来

1. **房主写世界。** 物理、气液热交换、病菌、AI、寻路、差事选择、物流、材料预留、随机结果和存档都在房主运行。客户端发送操作意图，显示等待、接受或拒绝。接受蓝图、复制人开始施工、建筑完工是三个分别可观察的状态。
2. **每人保留自己的操作环境。** 镜头、缩放、选择、叠层、面板开关、工具和拖动中的预览属于本机。暂停、倍速、日历和施工结果全局共享。若以后加队友光标或标记，单列为可选显示，不驱动他人视角。
3. **按读取成本分层。** 时钟和管理摘要按殖民地发布；地形、实体和动画按视区发布；完整库存、差事列表、配方队列和传感器详情在选中时订阅，关面板即释放。动画位置允许插值；资源余额、指令结果、网络开关和成员归属按权威版本显示。
4. **区分离开视区、隐藏和销毁。** 静态格子按世界与坐标标识；可移动或可替换对象使用会话内稳定的房主对象标识，并记录生命周期。拆了又建在同格的建筑必须有新身份。分页附范围与完整性，缺页先保留上次可信状态；只有明确删除或完整范围的快照才能清除。先取消选择和解绑面板，再释放显示对象。
5. **确定冲突与恢复规则。** 使用现有连接身份、命令序列和会话校验；对相同命令重复投递只执行一次。互斥设置携带预期版本，若已过期则返回最新值。框选按格反馈部分成功；资源争抢遵循原版蓝图、送材和预留规则，分别核对总量及占用。重连或房主重读档后废弃旧会话待办命令。视图落后先补对应区域或对象；无法追赶才重新入房。
6. **核对存档时点和首帧之间的变化。** 给用于比较的数据标记采样时刻或版本；覆盖“存档传完前建筑已拆、复制人已搬走、库存已变化”。入房完成时首个可操作视图须追上房主。协议增加字段时先定义默认值、边界、分页、版本协商和包大小，保留现有兼容样本；不兼容的运行组合在握手时给双方明确原因。

## Vanilla 同步工作清单

优先级按玩家遇到错误的影响排序。**P0** 解决对象认错、重复扣料、读旧值、不能恢复等一致性问题。**P1** 覆盖合作首版日常玩法。**P2** 是可用一份授权继续实现的扩展；其中低频写操作沿用首版房主代办范围。表中“验收”均可先在单份授权下取得分段证据。

| 优先级与领域 | 要开发或补测的状态与写操作 | 一份授权下的验收场景 |
|---|---|---|
| P0 会话、权限、时间 | 补测入房阶段、席位、版本、晚加入、断开、重连、房主关闭；核对暂停、倍速和周期显示。所有写入口都检查会话、角色和目标。 | 暂停中下单，恢复后才施工；下载中断后重入；旧连接命令到达新房间时世界不变。 |
| P0 地形、视区和迷雾 | 已有元素、质量、温度和可见性。补相变、真空、揭雾、边缘格、远距跳转、中心与周边重叠区的版本选择。 | 密室挖通后气体流动，水结冰；两端订阅不同区域再交换，比较同一版本格子的元素、质量及温度。 |
| P0 对象与施工生命周期 | 对齐蓝图、材料、朝向、占地、层、进度、建成、损坏、维修、拆除与取消。核对多格建筑点击任一格都定位同一对象。 | 两端同格下单；选中建筑时拆掉并原地重建；切视区回来，原蓝图、动作菜单和选中状态均正确。 |

可并行分工：协议与测试端负责消息合同、慢端与断线；房主侧负责权威读取、操作校验和夹具期望值；客机侧负责原版呈现、输入与清理。集成负责人统一变更线格式并串行调度真实游戏，避免三人分别给同一字段另起协议。新增物理量按现有线格式精度或界面显示精度比较，枚举、身份、数量、状态位和命令次数逐项精确比较。

## 单份授权的实测流程

1. **协议及对账。** 用两个协议端操作同一目标，第三端人为限速或掉线。注入延迟、重复、乱序的逻辑更新及截断，在分页和快照传输期间继续操作。分别核对健康端能推进、慢端有界、补同步后与房主同版本数据一致。
2. **真实房主录制。** 准备早期施工档和有管线、农业、生产的测试殖民地副本，先记录关键库存、设备和格子。向真实游戏发命令，保留房主变化前后读数、命令回执、快照和增量。缺少某种建筑时准备专门的小场景，报告中注明前置条件。
3. **真实客机回放。** 关闭房主，启动客机加载同一录制，使用原版控件触发输入；回放端核对具体对象、操作和参数再返回房主录制的结果。独立比对房主期望值与客机实际显示，避免只验证编解码自洽。检查隔离计数、截图、退回主菜单以及完整 Unity 日志。
4. **性能与产物。** 以现有预算回归主线程联机处理 p95 ≤4 ms、同档模拟速度下降 ≤15%、单端平均下行 ≤2 MiB/s。在同样负载下区分快照、持续视区、频繁查看详情的耗时；另外记录分页积压、被丢弃的旧页、内存和重新取全量的次数。每批先跑小场景，影响协议/采集负载的候选包再跑一小时。

现有入口如下。第二条需要一份 Vanilla 测试存档；第三条使用上一轮运行目录里的 `native-recording`。新增子系统要扩充这些夹具的动作和断言。[详细复测步骤](evidence/native.md) · [长稳及性能复现](evidence/qa/native-soak.md)

## 第二份授权到位后的第一局

用同一候选包、两个在线身份从 Steam 好友邀请进入同一殖民地。两人分开镜头，同时施工并争用材料；一人切换侧栏时另一人拆掉选中对象；客机掉线期间房主继续施工、保存，随后重邀，最后重开存档。记录两端身份不同的结果、画面、命令与房主日志。单机分段证据可提前验证每个组成部分；两个原生界面同时运行期间的竞态、Steam 身份路由、覆盖层邀请和实际体验在这一步取证。跨设备公网与四名真人的场景另行验收。
